## なぜ足すのか

0002 までの結果は「ダウンロード数は比べられない」という測り方の話で終わっている。一方、図を描いて見つけた Codex CLI の 8 日間の突出（2026-04-30〜05-06 と 05-11）は、海外で「Codex が npm で Claude Code の 12 倍」「利用者が Claude Code から流出」と報じられた週と重なっていた（[sources.md](../sources.md) 末尾）。広く報じられた数字が何だったのか、npm の伸びのうちどこまでが見かけで、どこからが本当の伸びかを、npm 以外の公開データで確かめる。

## 主張の型と、利益相反への追加の対処

「広く報じられた npm の数字は何だったのか」を公開データで確かめる。**どのツールが多く使われているかは引き続き主張しない。** 下書き・コード・集計は Claude Code（Anthropic 製）が担当し、今回の問いは「Anthropic に不利な報道の根拠を検証する」形になるので、0001 の対処に次を足す。

1. 「突出は異常値だった」と読める結果を書く節には、**Codex CLI の npm がその後も伸び続けた事実**（既知: 月別中央値で 2026-04 の 580,412 → 09 月の 3,483,414）を必ず併記する
2. 閾値は「人の流入」仮説に**甘く**置く（npm が約 49 倍に対し、代理指標は 1.5 倍で「整合」に数える）
3. Claude・Anthropic 側の出来事（モデル更新、不具合、利用枠）は、当事者の公表文だけを出典にし、評価を書かない。報道の説明は「報道はこう説明している」として引く
4. 結果が「人の流入と整合」なら、そのまま書く。Q1・Q2 の結論によらず記事化する（0001 の C は成立済み）

## 定義

- **日は UTC**。リポジトリは codex = `openai/codex`、claude = `anthropics/claude-code`、gemini = `google-gemini/gemini-cli`
- **突出の週 W** = 2026-04-30〜05-06（木〜水の 7 日）。**直前 4 週** = 04-02〜04-08、04-09〜04-15、04-16〜04-22、04-23〜04-29。週の比 = W の値 ÷ 直前 4 週の平均
- **月の比** = 2026-08（08-01〜08-31）の値 ÷ 2026-01（01-01〜01-31）の値
- **issue**: GitHub の GraphQL `repository.issues`（プルリクエストを含まない）を作成日時の昇順で全件。作成者の `__typename` が `Bot` のものは件数からも作成者からも除く。作成者が消えている（null）ものは件数には入れ、作成者の集計からは除く
  - (a) **issue 作成数** = 期間内に作成された issue の数
  - (b) **初めて issue を立てた人の数**（Q1）= そのリポジトリでの最初の issue の作成日が期間内にある作成者の数。**作成者数**（Q2）= 期間内に 1 件以上 issue を立てた作成者の数
- (c) **GitHub Releases の 1 日あたりダウンロード数**: 安定版 = `prerelease` も `draft` も false のリリース。リリース i のダウンロード数 D_i = 全アセットの `download_count` の合計。i が「最新の安定版」だった区間 I_i = [i の published_at, 次の安定版の published_at)（最後の版は取得時刻まで）。期間 P の値 = Σ_i D_i × |I_i ∩ P| ÷ |I_i| を P の日数で割ったもの（区間内は一様と仮定して按分）
- (d) **Hacker News の投稿数**: Algolia の公開 API で `tags=story` の投稿を期間ごとに全件取り、題名が次の正規表現（大文字小文字を区別しない）に合うものを数える。codex: `\bcodex\b`、claude: `\bclaude code\b`、gemini: `\bgemini cli\b`
- npm 側の既知の値（比べる相手）: 週の比 = 213,805,049 ÷ 直前 4 週の平均 4,346,512 = **49.2**。月の比 = 0 でない日の中央値で 2,525,795.5 ÷ 69,490 = **36.35**、数え方の係数 1 ÷ (1 − 0.5147) = 2.06 で割って **17.64**

## 既知の限界（結論に必ず添える）

1. issue・Hacker News・Zenn は「関心・困りごと」の代理で、利用者数ではない。issue は不具合の多さでも増える
2. Releases のダウンロード数は版ごとの累計で、時系列ではない。「最新だった区間に一様に付いた」と仮定して按分する。古い版ほど、最新でなくなった後のダウンロード（版を固定した CI など）が長く積もるので、**新しい月ほど低く出る偏り**がある。これは Q2 の予測（npm が代理指標を超える）に有利な方向の偏りなので、Q2 を支持と書くときは必ずこの偏りを添える。Q1 は 4〜5 月どうしの比較なので影響は小さい
3. Releases は、codex ではインストールスクリプトと Homebrew cask の取得元だが、claude では公式インストーラーの取得元ではない（`downloads.claude.ai`）。claude の Releases の値は主経路を映さない
4. Hacker News は英語圏の関心。`\bcodex\b` は OpenAI 以外の「codex」も拾う
5. 突出の週に「人の流入」が無かったと示せても、npm 以外の経路での増加や、その後の伸びの原因は分からない。版別の履歴が無いので、突出がどの版に付いたかも分からない
6. すでに npm の日次を見ているので、Q3 の段差の位置は知っている。Q3 は記述にとどめる
