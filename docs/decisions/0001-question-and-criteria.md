## 主張の型

「npm のダウンロード数は、配布のしかたの違いのせいで、ツール間の人気の比較に使えないのではないか」を公開データで確かめる。**どのツールが多く使われているかは主張しない。** 3 ツールに同じ指標を当てる。

## 定義

- **日**は UTC（npm の集計単位）。**取得日の 2 日前まで**を使う（当日・前日は未確定のことがあるため）
- **安定版** = 版の文字列に `-` を含まない版。公開時刻はレジストリの `time`
- **リリース日** = 安定版が 1 つ以上公開された UTC の日
- **プラットフォーム版（Codex）** = 版の文字列が `-darwin-arm64`・`-darwin-x64`・`-linux-arm64`・`-linux-x64`・`-win32-arm64`・`-win32-x64` のどれかで終わる版
- **E** = `@openai/codex` 0.99.0 の公開日（UTC）。レジストリで 2026-02-11。optionalDependencies が `npm:@openai/codex@<版>-<プラットフォーム>` の形になった最初の安定版

## 予測と判定（値を見る前に凍結）

| # | 予測 | 指標 | 判定 |
|---|---|---|---|
| **P1a** 二重計上（直接） | Codex は 1 インストールで本体とプラットフォーム版の 2 つが同じパッケージ名で数えられている | 版別ダウンロード数（直近 7 日、`/versions/@openai%2Fcodex/last-week`）で、s = プラットフォーム版の合計 ÷ 全版の合計 | s が **0.40 以上**なら支持（理論値は 0.5）、**0.20 未満**なら不支持、間は保留 |
| **P1b** 段差（履歴） | E の前後で `@openai/codex` の日次ダウンロード数が段差的に増えた | 後 28 日（E+14〜E+41 ＝ 2026-02-25〜03-24）の中央値 ÷ 前 28 日（E−28〜E−1 ＝ 2026-01-14〜02-10）の中央値を 3 パッケージで出し、Codex の比 ÷ 他 2 つの比の算術平均 | **1.5 以上**なら支持、**1.2 未満**なら不支持、間は保留。交絡: 同じ時期の Codex 固有の需要増（製品発表など）は差の差では消えない。P1a が不支持なら、P1b が 1.5 以上でも「数え方のせい」とは書かない |
| **P2** リリース日の跳ね | 自動更新があるなら、リリース日とその翌日はダウンロード数が多い | ツールごとに、直近 180 日の**平日（月〜金、UTC）だけ**で、「リリース日または前日がリリース日」の日の中央値 ÷ それ以外の平日の中央値 | **1.2 以上**なら「リリース日に跳ねる」、未満なら「跳ねない」。どちらかの群が **20 日未満**なら判定不能 |
| **P3** 経路による順位（記述） | npm の順位と Homebrew の順位は一致しない | npm の直近 30 日の合計の順位と、Homebrew の 30d の install 数の順位（claude = cask `claude-code` ＋ `claude-code@latest`、codex = cask `codex`。formula `codex` は同じツールだと確認できた場合だけ足す、gemini = formula `gemini-cli`）。90d・365d も並べる | 判定なし。一致・不一致をそのまま書く |
| 記述 | ── | (a) Claude Code のプラットフォーム別 8 パッケージの直近 30 日の構成比（Linux の割合）、(b) 3 パッケージの平日 ÷ 週末の比（直近 180 日）、(c) Claude Code がバイナリを別パッケージにした 2026-04-13 の前後 28 日の中央値の比（P1b と同じ窓の取り方）、(d) Gemini CLI の火・水 vs 他の平日（安定版が毎週火曜 20:00 UTC のため）、(e) 3 パッケージの日次の推移の図 | 判定なし |

## 撤退基準

| # | 基準 | 定義 | 破棄ライン |
|---|---|---|---|
| **A** | データ到達 | 3 パッケージの日次が、各パッケージの公開日から取得日の 2 日前まで、日付の欠けなく返る。レジストリから全安定版の公開時刻が取れる | どちらかが欠けたら破棄。Homebrew だけ取れない場合は P3 を落として続行、版別だけ取れない場合は P1a を落として続行 |
| **B** | 整合性 | 3 パッケージそれぞれで、明示した 30 日間の `range` の合計と、同じ期間の `point` の値 | 差が **±1% を超えたら**破棄 |
| **C** | 新規性 | P1a・P1b・P2 のうち 1 つ以上で「支持」か「不支持（跳ねない）」が出る | 方向によらず記事化する。すべてが保留・判定不能なら記事化しない（撤退の記録だけ残す） |

### 見直しの規則

- 本決定のコミット以降、定義・窓・閾値・対象パッケージを変えない。**禁止**: 値を見た後に窓や閾値を動かすこと、都合の悪いツールを外すこと、問いを足して C を満たすこと
- 事前登録に無い集計は「事後の参考表」として別ファイルに分け、判定に使わない

## 既知の限界（結論に必ず添える）

1. npm のダウンロード数は利用者数ではない（CI、ミラー、ボット、再インストールを含む。npm 公式の説明は記事を書く前に読む）
2. 3 ツールとも npm 以外の経路がある（Claude Code はネイティブインストーラーが推奨、Codex はシェルスクリプトが先頭、Homebrew・WinGet・apt など）。npm 以外の経路の利用者数は公開データでは分からない。Homebrew の analytics は、analytics を無効にしていない利用者だけの数
3. 版別のダウンロード数は直近 7 日しか取れないので、P1a は「今」の状態しか示せない
4. P2 は「自動更新」と「リリース告知を見た人の手動更新」を区別できない
5. 観測は 2025-02〜2026-09 の 1 回の取得

## 別枠: 記事の「型」の実験（分析の判定とは独立）

ユーザーの仮説「題材の選び方で閲覧数が変わる」を 6 本目で試す（経緯は非公開の備忘）。基準値は既存記事の公開 3〜4 日後の閲覧数（43 と 150）。**公開 3〜4 日後の Zenn ダッシュボードの閲覧数が 100 以上なら「型は再現した」、60 未満なら「前回は外れ値だった」、間は保留。** 公開は平日、前の公開（2026-09-21）から 14 日以上あける。
