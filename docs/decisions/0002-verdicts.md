## 記事で言えること・言えないこと

言える（事実）:
- `@openai/codex` の直近 7 日のダウンロード数の 51.5% は、プラットフォーム別バイナリの版に付いている。Claude Code と Gemini CLI には、この数え方は無い（0）
- したがって、3 つのパッケージ名のダウンロード数をそのまま並べると、Codex CLI だけ 1 インストールが約 2 回に数えられた数を比べることになる
- P3 の 30 日・90 日では npm と Homebrew の順位は一致した（予測は外れた）

言えない:
- どのツールの利用者が多いか（npm 以外の経路の数が無い。ダウンロード数は利用者数ではない）
- Codex CLI の 2026-02 以降の増加のうち、どれだけが数え方のせいか（版別の履歴が無い）
- リリース日に自動更新で跳ねるか（P2 の判定は弱く、Claude Code は判定不能）

## 事前登録からの逸脱と、取得後に決めたこと（正直に）

1. **Homebrew analytics の JSON の形が想定と違った**（`items` の配列ではなく、名前 → オプション違いの行のリスト）。取得後に構造だけを確認し、install 数を表示する前に「同じ名前の行（`gemini-cli --HEAD` など）は合算する」と決めて修正した（ea513a7）。P3 は判定なしの記述で、`--HEAD` の行は小さい
2. **formula `codex`**: 取得前に決めた確認方法（Homebrew のメタデータの homepage）は、API が 404 だったので使えなかった → 事前の決めどおり P3 には足していない。値を見た後に homebrew-core の履歴（`Formula/c/codex.rb`、2025-10-17 のコミット「codex: remove formula to prepare for cask migration」、削除直前の homepage は `https://github.com/openai/codex`）と `tap_migrations.json`（`"codex": "homebrew/cask"`）で同じツールだと確認した。足した場合の数は posthoc.md に分けた。一致・不一致の結論はどちらでも同じ
3. **値が 0 の日**: 0001 の A は「日付の欠け」で定義しており、取得前にコミットした実装も日付の有無で判定し、0 の日は別に数えて報告する作りだった。定義どおり通過とし、影響は posthoc.md で確認した（P1b の窓には 0 日）
4. **P2 の指標の弱点**（トレンドとの交絡）は結果を見てから気づいた。判定は事前登録どおりに残し、記事では「跳ねる」を主張の柱にしない
