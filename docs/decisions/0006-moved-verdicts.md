## 記事で言えること・言えないこと

言える（事実）:
- Anthropic 自身が、2026-03-04〜04-20 に Claude Code の品質に影響する変更が 3 つあったと公表している（04-23）。同じ 04-23 に GPT-5.5 が出ている
- その期間、Claude Code の issue に占める「品質」「利用枠・料金」の語の割合は 1.3〜1.5 倍に増えていた。事前に決めた支持の線（1.5 倍）には届いていない
- 規則が拾った題名を読んで補正すると、Claude Code では利用枠・料金への不満が約 3 倍、品質への不満が約 2 倍（事後の確認。標本 40 件ずつ、数えたのは Claude）。Codex CLI はほぼ横ばい。**Anthropic に不利な方向の結果で、同じ重さで書く**
- 04-20 以降、Claude Code の issue は全部の区分で減ったが、どの区分も 1〜2 月を上回ったまま
- 題名で「乗り換え」を言う issue は数件。多いのは互いを手本にした機能要望と、両方を併用する人の不具合
- Gemini CLI は 2026-06-18 に個人アカウント向けの提供を終了している（公式アナウンス）。それでも npm は 1 月の 0.90 倍
- 「完了」として閉じられた issue は、3 つとも全体の約 1 割

言えない:
- 不満が増えたから人が動いた、という因果。GPT-5.5 が引いたのか、Claude 側の不満が押したのか、の切り分け
- Claude Code の issue が 5 月に減ったのが、修正のためか、利用が減ったためか
- どちらがいいか（出力の質と、料金あたりの価値は公開データで比べられない）

## 事前登録からの逸脱と、集計後に決めたこと（正直に）

1. **語の規則が粗かった**: 適合率は 28〜68%（`[MODEL]` は 90% 以上）で、しかも期間で違った（P0 ほど無関係な題名が多い）。このため、規則そのままの比（1.42・1.47）は実際の増え方を小さく見せている可能性が高い。0005 の規律 6 のとおり適合率を数えて併記したが、**判定は事前登録どおり「保留」のまま**にした。題名を読む前に規則を決める以上、避けにくい弱点だが、規則の語ごとに「無関係に当たりそうな使われ方」を先に挙げておけば減らせた
2. **適合率を数えたのは Claude**（下書きと集計の担当で、Anthropic 製）。不満かどうかの線引きは `scripts/posthoc_moved_precision.py` の冒頭に書いた。どちらとも取れる題名は別に数え、厳しい数え方と緩い数え方の両方を `docs/data/moved_precision.json` に残した
3. **R3 は設計の時点で数が足りなかった**: 相手への言及は題名にほとんど出ない（P0 で 5 件）。判定不能は 0005 の規則どおり。代わりに該当の全件を読み、内訳を事後の参考として出した
4. **比較表に 1 行足した**:「完了として閉じた割合（全件に対して）」は、0005 で定義した 2 つの数（閉じた割合 × 閉じた理由の内訳）の積。新しい取得や定義は足していない
5. **R1m は、ユーザーの承認後・凍結前に足した**（0005 に記載のとおり）。結果は R1a と同じ「保留」で、どちらか一方を選んで書く余地は無かった
6. 集計の途中でスクリプトが 1 度落ちた（追加取得の途中で「issue への対応」の対象が 0 件だった）。表示だけの修正で、定義は変えていない
