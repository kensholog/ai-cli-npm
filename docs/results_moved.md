## 事後の参考（0005 の規律 6。判定は変えない）

### 1. 語の規則はどれだけ当たっていたか

規則に合った題名を区分 × 期間ごとに最大 40 件、無作為に取り（種 20260922）、Claude が読んで数えた。適合率の誤差は ±15 ポイントほどある。

| 区分 | 適合率 P0 → P1 → P2 | 補正後の割合 P0 → P1 → P2 | 補正後の比（P1 ÷ P0） |
|---|---|---|---:|
| Claude Code・品質 | 50% → 68% → 57% | 0.62% → 1.19% → 0.81% | **1.9** |
| Claude Code・`[MODEL]` | 92% → 95% → 90% | 0.84% → 1.11% → 0.99% | 1.3 |
| Claude Code・利用枠・料金 | 28% → 60% → 55% | 1.00% → 3.20% → 3.06% | **3.2** |
| Codex CLI・品質 | 33% → 50% → 40% | 0.24% → 0.34% → 0.32% | 1.4 |
| Codex CLI・利用枠・料金 | 65% → 55% → 48% | 1.68% → 1.91% → 1.88% | 1.1 |

- 規則は粗かった。「品質」語は lazy-load の機能要望や UI の速度低下を、「利用枠・料金」語は「ステータス行に利用枠を表示してほしい」という要望や、Max plan が文脈として出るだけの不具合を拾っていた。P0 ほど無関係な題名の割合が高い
- 補正すると、**Claude Code では利用枠・料金への不満が約 3 倍、品質への不満が約 2 倍に増えていた**（Anthropic に不利な方向の結果。0005 の規律 5 により同じ重さで書く）。Codex CLI はほぼ横ばい。**事前登録の判定（保留）は変えない。** 補正は結果を見た後の確認で、標本は 40 件ずつ、数えたのは Claude である
- 利用枠・料金への不満は P2 でも 3.06% と高いまま。Anthropic は 04-23 に利用枠をリセットしたと書いているが、不満の割合は下がっていない

### 2. 相手への言及の中身（全件を読んだ）

| | P0 | P1 | P2 |
|---|---|---|---|
| Claude Code の issue（Codex・OpenAI・GPT に言及） | 5 件: 機能要望 2、相互運用 2、他 1 | 14 件: **乗り換え・不利な比較 2**、機能要望 4、Codex プラグイン・相互運用 6、他 2 | 22 件: **乗り換え・不利な比較 5**、機能要望 6、Codex プラグイン・相互運用 6、他 5 |
| Codex の issue（Claude・Anthropic に言及） | 5 件: すべて「Claude Code のこの機能がほしい」 | 9 件: 機能要望 6、他 3 | 20 件: 機能要望 10、**Claude Code からの移行・相互運用の不具合 7**、他 3 |

- 「Codex に移る」と題名で言い切る issue は実在するが、P2 の 10,522 件のうち数件
- 多いのは、互いを手本にした機能要望と、**両方を一緒に使う人の不具合**（Claude Code の中から Codex を呼ぶプラグイン、Codex が CLAUDE.md や Claude Code のプラグインを読む機能、設定の移行）。題名から見える範囲では、「乗り換え」より「併用」と「互いの機能の取り込み」が目立つ

## 限界（0005 のとおり）

1. 題名の語は不満を取りこぼし、無関係な題名も拾う（適合率 28〜95%）。補正は 40 件ずつの標本で、数えたのは Claude
2. issue は利用者のごく一部が書く。割合が増えても、利用者全体の不満が増えたとは限らない
3. 時期が重なっているだけで、因果は言えない。04-23 には Anthropic の公表文・利用枠のリセットと GPT-5.5 が重なっている
4. `[MODEL]` テンプレートは Claude Code にしか無く、対照が取れない
5. 「issue への対応」は運営の方針を映す指標
